What is predicted? And how does this map to the code?+

The hidden state is the guidance.

At step t, the Time Decoder computes a context-dependent hidden state hₜ from available history. A learned connector maps hₜ to a sequence of four latent prefix vectors Pₜ. This prefix is injected into the Note Decoder before it autoregressively generates the events of bar t. The guidance is latent, not a set of already-generated notes.

history → hₜ → Pₜ = MLP(hₜ) → xₜ,₁ → xₜ,₂ → … → STO

“Predicting guidance” means producing a learned latent representation used to predict the next bar’s events. It does not mean that the implementation has a separate supervised target or loss for future hidden states.

A deliberate simplification.

The main animation shows the conceptual cycle: finish bar t, summarize it, and use the feedback for the next step. The current main branch partitions history: bar t’s raw NOTE events go directly into the next bar’s Note Decoder, while its summary enters the Time Decoder one step later (when generating bar t+2). The animation omits this routing detail to keep the two autoregressive axes visible.

Each row represents one bar; each horizontal step represents a musical event, not necessarily a single note. Notes here are illustrative glyphs; actual events can also describe beats, instruments and other structure. STO ends a bar. Four bars and their event counts are only a demonstration, not model limits.
